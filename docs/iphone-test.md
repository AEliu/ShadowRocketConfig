## 准备与导入

1. 保存原配置副本，在 App 内确认节点可用。首次优先导入离线版；版本基线为 2.2.93。
2. 全局路由选“配置”；关闭会覆盖 DNS/规则的模块，记录按需连接、代理类型、包含所有网络/强制路由/本地网络排除等开关。开启本地网络权限及 DNS/代理日志；测试后按需关闭日志。
3. 在配置通用设置确认 `direct-dns-server`、`proxy-dns-server` 等没有被忽略；保存再导出检查关键字段。精简版确认 4 个 RULE-SET 下载成功，预览非空。
4. 使用 App 的规则测试及实际连接日志，确认下表策略。日志比“网页打开了”更有证明力。

| 测试对象 | 预期 |
| --- | --- |
| 百度、B 站、QQ、淘宝 | DIRECT；国内 DoH；和 VPN 关闭时比较访问耗时与 CDN IP/地区 |
| `apps.apple.com`、App Store 更新 | Apple 例外 DIRECT；不要把所有 apple.com 子域都假定直连 |
| GitHub、Google、OpenAI | PROXY；出口与所选节点一致 |
| 自己可控的、列表外新域名 | FINAL,PROXY；使用随机子域规避缓存 |
| `192.168.x.x` NAS/路由器、打印机、AirPlay、`.local` | 局域网访问/发现正常；mDNS 允许留在 LAN |
| `nas.home.arpa` | 先配置实际 Host 或局域网 DNS，再验证；公共 DNS 不会替你知道内网名称 |

如需证明自定义优先级，临时加 `DOMAIN,www.baidu.com,PROXY`，构建并导入，确认实际日志变为 PROXY，再删除并重建。不要只用 IP 规则去覆盖域名规则来推断顺序。

## DNS 路径与泄漏

1. 先在无 VPN 状态记录网络和出口。然后打开 VPN，清除可清除的 App DNS 缓存并重连，使用可控域名的随机子域，避免旧连接或缓存误导。
2. 对国内直连域名、代理域名、未匹配域名分别发起 A、AAAA 查询；有工具时补测 TXT、SRV、HTTPS/SVCB。记录 Shadowrocket DNS 日志、连接日志、解析结果和目标域名的权威 DNS 日志（若有）。代理域名可能由节点的递归 DNS 解析，不要求一定显示 Google/Cloudflare。
3. 在可控路由器/AP 上抓取 iPhone 客户端地址的出站流量，重点检查 UDP/TCP 53、853，以及到 DoH IP 的 443。推荐过滤条件思路：`host <iPhone-IP> and (port 53 or port 853)`；同时抓 IPv6。iPhone 经 VPN 的外层流量只应体现节点连接；国内 DoH 的 443 直连是预期行为。
4. 暖启动：代理/未知业务域名不应以明文 DNS 发到本地 ISP/路由器，也不应通过国内 DoH 直连解析；冷启动：单独识别 `dns.alidns.com`、`doh.pub` 引导解析，记录实际是否使用系统 DNS。TLS 加密下抓包看不到查询名，需要结合客户端及权威日志，不能只看 443 流量推断内容。
5. 用支持指定服务器的 iPhone 网络工具，对 `8.8.8.8:53`、`223.5.5.5:53` 分别执行 UDP 与 TCP 查询，确认列出的公共 DNS 劫持生效；对路由器 DNS 查询内网域名，确认局域网没有被破坏。未列出的 DNS 地址不保证被接管。
6. 用 DNS 泄漏测试网页辅助观察。单次“显示某地区/某家 DNS”不足以判定：国内业务使用中国 DNS 是预期，代理节点自带 DNS 也可能与出口不同。WebRTC/STUN 泄漏和 DNS 泄漏是两回事，视频通话需另测。

若无法获得抓包或足够日志，把结论写为“未验证”，不要写“零泄漏”。VPN 关闭、崩溃或切换间隙不受此配置完整保护。

## 故障、IPv6 与稳定性

- 在自己可控的测试网络临时阻断国内两家 DoH 的 443，再访问国内域名：观察是否转到经代理的备用 DNS，而不是系统明文 DNS。由于解析视角改变，CDN 位置可能变化。还要分别阻断默认/备用 DoH，确保失败时没有业务流量悄悄 DIRECT。
- 暂时选失效节点：国外/未知业务应失败，国内已命中 DIRECT 的业务在国内 DNS 可达时应继续工作。再恢复节点，确认可恢复；这不证明断开整个 VPN 后有 kill switch。
- 节点不支持 UDP 时测试视频、语音和 QUIC：应拒绝无法代理的 UDP，不允许自动直连；若 App 能回退 TCP 可继续使用，否则需要支持 UDP 的节点。
- 分别用 Wi-Fi、蜂窝、双栈 IPv6 网络测试 IPv4/IPv6 出口和 DNS。若有 IPv6-only/NAT64 网络，单独测试 DoH IP URL、节点启动及 LAN 行为；不要用双栈测试代替。
- 切换 Wi-Fi ↔ 蜂窝、飞行模式恢复、锁屏 10 分钟后恢复，重复国内/国外访问与消息推送。需要反复强退 App 才恢复，视为未通过。
- 对局域网设备测试 Bonjour 发现、文件访问、打印/AirPlay。若开启“包含所有网络/强制路由”后失败，对照 App 的本地网络排除设置再测试，不盲目扩大公网 TUN 旁路。
